# Buffer overflow and incomplete mediation

- Document: c04 (course)
- Source: Written for this project from the topics of the CoSc4035 Computer Security course slides (Jimma University), Chapter 2
- Licence: CC BY 4.0

Program flaws are unwanted program behaviours caused by vulnerabilities in code. Two common flaws are buffer overflows and incomplete mediation.

When a program runs, each variable is given a fixed-size block of memory, called a buffer. A buffer overflow happens when the program writes more data into a buffer than it can hold. The extra data spills into neighbouring memory and overwrites whatever was stored there. In a buffer overflow attack, the attacker deliberately supplies more input than the buffer can take. Depending on what is overwritten, the attacker can crash the program, change important values, change which code runs next, or inject malicious code and have it executed. Buffer overflows were long treated as a minor annoyance, but the many security holes that come from them show that developers must take them seriously.

Mediation means checking that the input a user gives is a meaningful, valid request before acting on it. Incomplete mediation happens when an application accepts bad data. A program should at least catch entries that are badly formed (a date of birth of 31 April), unreasonable (a birth year of 1876) or inconsistent with other entries. Unchecked input can also be an attack: a very long value may cause a buffer overflow, and a value containing SQL commands may lead to SQL injection.

Many web forms do client-side mediation: JavaScript in the browser checks the fields before the form is sent. This makes the form friendlier to use, but it gives no security. A user can switch off JavaScript, edit the form or its hidden fields before sending it (for example change a hidden price field from 111.00 to 50.00), or skip the browser and send requests to the server directly. The defence is server-side mediation: the server must carefully check every value it receives, whatever its length or content, and make sure that any state kept by the client has not been changed.
