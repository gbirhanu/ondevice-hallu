# Public-key cryptography and RSA

- Document: c10 (course)
- Source: Written for this project from the topics of the CoSc4035 Computer Security course slides (Jimma University), Chapter 3, part 2
- Licence: CC BY 4.0

In asymmetric, or public-key, cryptography each user has a pair of keys. The private key is known only to its owner, and the public key can be given to anyone. Data encrypted with one key of the pair can only be decrypted with the other. The idea was introduced by Diffie and Hellman in 1976.

The key pair can be used in different ways. For confidentiality, the sender encrypts a message with the receiver's public key; only the receiver, who holds the matching private key, can read it. For authentication, the sender encrypts with their own private key; anyone can decrypt it with the sender's public key, and this shows who sent it. For both at once, the sender first encrypts with their own private key and then with the receiver's public key. Public-key systems are used for three purposes: encryption and decryption, digital signatures, and key exchange.

RSA, named after Rivest, Shamir and Adleman, is the best-known public-key algorithm and is used for both encryption and digital signatures. Its security rests on the fact that no efficient method is known for finding the prime factors of a very large number. Keys are generated as follows:
1. Choose two large random prime numbers, p and q.
2. Compute n = p x q and phi = (p - 1)(q - 1).
3. Choose e between 1 and phi so that e and phi have no common factor other than 1.
4. Compute d so that e x d leaves a remainder of 1 when divided by phi.
5. The public key is (n, e) and the private key is (n, d). The values d, p, q and phi must be kept secret.
To encrypt a message m, the sender computes c = m^e mod n, and the receiver decrypts with m = c^d mod n. In a small example with p = 11 and q = 3, n = 33, phi = 20, e = 3 and d = 7; the message 7 encrypts to 13, and 13 decrypts back to 7.

RSA is much slower than symmetric ciphers: in hardware it is about 1,000 times slower than DES, and in software the gap is about 100 times. For this reason public-key methods are mostly used to exchange a symmetric session key, which then encrypts the actual data.
