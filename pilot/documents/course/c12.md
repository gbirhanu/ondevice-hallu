# IP Security (IPSec)

- Document: c12 (course)
- Source: Written for this project from the topics of the CoSc4035 Computer Security course slides (Jimma University), Chapter 4
- Licence: CC BY 4.0

The IP protocol itself offers no protection: packets can be read and changed as they cross a LAN, a switch or a router, and even encrypted traffic is open to traffic analysis. IP Security (IPSec) adds security at the network layer, so it protects all applications, including those that have no security features of their own. Because it works below TCP and UDP, it is transparent to applications and to users.

IPSec provides origin authentication, confidentiality, message integrity, replay detection and key management for IP packets. It uses two protocols:
- The Authentication Header (AH) shows that a packet came from the source named in its header and was not changed on the way. It also protects against replay, but it does not encrypt.
- The Encapsulating Security Payload (ESP) encrypts the data to stop eavesdropping and can also authenticate it. ESP can do the work of AH as well, but it needs more processing.
The keys that these protocols need are exchanged with the Internet Key Exchange (IKE) protocol.

Both AH and ESP can work in two modes. Transport mode is used when both end hosts support IPSec; it protects the TCP or UDP segment but not the IP header. Tunnel mode protects the entire original IP packet, header included, by placing it inside a new packet with a new header. It is used between security gateways such as routers and firewalls when the end hosts do not support IPSec, and because the new header carries the gateways' addresses, it also helps against traffic analysis.

Before protected packets are sent, the two sides set up a security association (SA), a logical connection that records the algorithms, keys and key lengths they will use. An SA works in one direction only, so two-way traffic needs two SAs. Each SA is identified by three things: a 32-bit Security Parameter Index (SPI) chosen by the receiver and carried in every AH or ESP header, the destination IP address, and whether the SA uses AH or ESP. Typical uses of IPSec include virtual private networks between branch offices and secure remote access over the Internet.
