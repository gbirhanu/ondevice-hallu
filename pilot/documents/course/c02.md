# Passive and active attacks; security services

- Document: c02 (course)
- Source: Written for this project from the topics of the CoSc4035 Computer Security course slides (Jimma University), Chapter 1
- Licence: CC BY 4.0

Security attacks are commonly divided into passive and active attacks.

A passive attack tries to learn or use information from a system without changing any system resources; the attacker only listens or watches. There are two types. In release of message contents, the attacker reads the content of a telephone call, an e-mail or a transferred file. In traffic analysis, the attacker may not be able to read the content, for example because it is encrypted, but studies the pattern of communication: which hosts are talking, where they are, and how often and how long they exchange messages.

An active attack changes system resources or affects how they work. There are four categories:
1. Masquerade: the attacker pretends to be someone else.
2. Replay: the attacker captures a data unit and sends it again later to produce an unauthorised effect.
3. Modification of messages: part of a legitimate message is changed, or messages are delayed or put in a different order.
4. Denial of service: the attacker prevents or disrupts the normal use or management of communication facilities.

To counter these attacks, the OSI security architecture defines a set of security services:
- Authentication assures the receiver that a message really comes from the source it claims to come from.
- Access control limits and controls who can reach host systems and applications over communication links.
- Data confidentiality protects transmitted data from passive attacks.
- Data integrity comes in two forms. A connection-oriented service protects a whole stream of messages and makes sure they arrive exactly as they were sent: nothing is duplicated, inserted, changed, reordered or replayed. A connectionless service treats each message separately, without regard to the others, and usually protects only against changes.
- Non-repudiation stops either the sender or the receiver from denying that a message was sent or received.
- Availability keeps a system usable on demand by authorised users; it is the service that addresses denial-of-service attacks.
